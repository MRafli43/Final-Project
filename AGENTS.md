# Project instructions

## Mandatory decision documentation

For every implementation task:

1. Read `docs/README.md` and relevant existing decision records.
2. If introducing a technical choice, dependency, tool, architecture, or development workflow, document the decision in `docs/decision/` as part of the same task, without waiting for a separate request.
3. Follow the numbering, template, and status labels in `docs/README.md`.
4. Update the documentation index when adding a record.
5. If replacing an existing decision, preserve it, mark it `superseeded`, and link it to the replacement.
6. Do not create records for routine commands or changes that introduce no meaningful decision.
7. Before finishing, check whether documentation needs updating and report which records changed.
